Lancer avec Docker

Tout l'environnement (base de données, backend, frontend) tourne dans Docker Desktop. WAMP n'est plus nécessaire.

Prérequis

  • Docker Desktop installé et démarré (Docker Compose v2 inclus).
  • Un fichier backend/.env contenant au minimum TMDB_API_KEY et JWT_SECRET. Modèle : backend/.env.example.
  • Les ports 8080 et 3307 libres sur la machine.

Premier lancement

cd C:\wamp64\www\tv-tracker
docker compose up -d --build

Puis ouvrir :

  • Application : http://localhost:8080
  • Documentation : http://localhost:8080/documentation

Vérifier que tout tourne

docker compose ps
docker compose logs backend --tail 20

Résultat attendu : db est healthy, backend est healthy, et les logs du backend affichent Migration terminée, puis Backend démarré sur http://localhost:5000.

Commandes courantes

ActionCommande
Arrêter les conteneurs (données conservées)docker compose down
Redémarrerdocker compose up -d
Reconstruire après une modification de codedocker compose up -d --build
Relancer seulement les migrationsdocker compose restart backend
Suivre les logs en directdocker compose logs -f backend
Ouvrir un shell MySQLdocker compose exec db mysql -uroot -proot_local tv_tracker
Réinitialiser la base (efface toutes les données). docker compose down -v supprime aussi le volume tv-tracker_db_data. Au prochain up, la base est recréée vide et les migrations s'appliquent. Ne pas lancer cette commande sans avoir sauvegardé les données.

Ce que contient la configuration

ÉlémentDétail
RéseauUn réseau interne tv-tracker_default. Les services se joignent par leur nom : db, backend.
Volumedb_data : données MySQL persistantes.
DocumentationLe dossier ./documentation est monté en lecture seule dans Nginx. Modifier une page n'exige pas de reconstruire l'image.
SecretsLus depuis backend/.env au lancement, jamais copiés dans l'image (voir backend/.dockerignore).
Healthcheck MySQLmysqladmin ping toutes les 5 secondes. Le backend attend qu'il soit healthy avant de démarrer.
Redémarragerestart: unless-stopped : les conteneurs repartent avec Docker Desktop.

Variables surchargées dans Docker

Le fichier backend/.env peut contenir des valeurs pensées pour WAMP (DB_HOST=localhost). Le docker-compose.yml les remplace pour le backend :

VariableValeur dans Docker
DB_HOSTdb
DB_PORT3306
DB_NAMEtv_tracker
DB_USER / DB_PASSWORDtvtracker / tvtracker_local (par défaut, modifiables via un fichier .env à la racine)
FRONTEND_ORIGINhttp://localhost:8080

Le compte root de MySQL a pour mot de passe root_local (variable MYSQL_ROOT_PASSWORD). Il n'est utilisé que pour l'administration de la base.

Connexion à la base depuis un outil externe

Hôte localhost, port 3307, base tv_tracker, utilisateur tvtracker, mot de passe tvtracker_local.

Pour changer les mots de passe par défaut, crée un fichier .env à la racine du projet (à côté de docker-compose.yml) avec MYSQL_ROOT_PASSWORD, DB_USER et DB_PASSWORD, puis relance avec docker compose down -v et docker compose up -d --build (la base doit être recréée car le mot de passe est fixé à sa création).
