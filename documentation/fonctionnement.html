Fonctionnement métier

Les règles qui font vivre l'application : statuts, synchronisation TMDB, tâche planifiée, import et sécurité.

Statuts d'une série

Chaque utilisateur a son propre statut pour chaque série (table show_tracking).

ValeurLibelléMis à jour automatiquement ?
to_watchÀ voirNon
watchingEn coursOui, retour depuis « Terminé » si un épisode redevient non vu
pausedEn pauseNon
completedTerminéOui, dès que tous les épisodes sont vus par cet utilisateur
droppedAbandonnéNon

Le calcul est fait par refreshShowCompletion (backend/src/services/showStatus.js). Un épisode absent de watch_status pour l'utilisateur est considéré comme non vu.

Synchronisation TMDB

syncShowFromTmdb (services/showSync.js) crée ou met à jour une série, puis ses saisons et ses épisodes, à partir de son identifiant TMDB. Quelques règles importantes :

  • Saison 0 ignorée : les « Spéciaux » (bonus, making-of) ne sont pas importés.
  • Durées plausibles seulement : toute durée supérieure à 240 minutes ou inférieure ou égale à 0 est ignorée (valeur mise à NULL). TMDB contient parfois des erreurs de saisie qui fausseraient les statistiques.
  • Langue : toutes les requêtes TMDB sont faites en fr-FR.
  • Réessais : sur une erreur 429 (limite de débit) ou 5xx, le client réessaie jusqu'à 5 fois avec un délai croissant, ou selon l'en-tête Retry-After.
  • Délai maximum : 10 secondes par requête, pour qu'un appel bloqué ne fige pas une route.
  • Fraîcheur : une série synchronisée il y a moins de 24h n'est pas redemandée à TMDB lors d'un ajout ou d'un aperçu. Le bouton « Rafraîchir » et la tâche planifiée forcent la mise à jour.
  • Upserts : les écritures utilisent INSERT … ON DUPLICATE KEY UPDATE, une requête par saison pour les épisodes. Deux synchronisations simultanées ne créent pas de doublon.
  • Cache mémoire : tendances (30 min), genres (24 h), recherches (10 min) et détails de la watchlist (1 h) sont gardés en mémoire du backend, et perdus à son redémarrage.

Tâche planifiée

Chaque jour à 6h00, heure de Paris (cron défini dans cron/checkNewEpisodes.js), le backend resynchronise toutes les séries suivies par au moins un utilisateur avec le statut watching ou to_watch. Cela fait apparaître les nouveaux épisodes et saisons annoncés sur TMDB. Une série en erreur est journalisée et n'empêche pas les suivantes. Si une exécution est encore en cours à l'heure suivante, la nouvelle est ignorée.

La tâche tourne dans le conteneur backend. Elle n'a lieu que si ce conteneur est démarré à 6h. Pour la tester sans attendre, il faut la déclencher manuellement (par exemple via POST /api/shows/:id/refresh).

Revisionnage

Une même personne peut revoir un épisode. La colonne watch_count compte les visionnages : elle vaut 1 à la première vision et augmente avec le bouton ↻ (POST /api/episodes/:id/rewatch). Les épisodes marqués vus avant l'introduction de cette colonne ont été mis à 1 par la migration.

Import

Deux mécanismes existent :

  • Import générique (POST /api/import) : pour chaque série du JSON, la première correspondance TMDB est retenue. Le rapport renvoyé indique le titre trouvé et le nombre d'épisodes marqués. Attention : une recherche ambiguë peut donc associer la mauvaise série. Vérifier le rapport.
  • Import TV Time (backend/scripts/import-tvtime.js, commande npm run import:tvtime) : script ponctuel qui lit un fichier JSON généré à partir de l'export RGPD TV Time. Option --user=pseudo pour cibler un compte. Le fichier scripts/tvtime-payload.json n'est pas dans le dépôt et doit être régénéré.

Statistiques

La page Stats agrège le temps de visionnage (mois, jours, heures), la répartition par genre et l'évolution mensuelle. Le temps repose sur les durées d'épisodes et de films : une durée aberrante ou absente fausse le total. La page propose donc deux actions de maintenance : « Nettoyer les durées aberrantes » et « Corriger les durées manquantes » (routes clean-runtimes et refresh-runtimes).

La configuration decimalNumbers: true du pool MySQL renvoie les SUM() et AVG() en nombres et non en texte, ce qui évite des erreurs d'addition côté JavaScript.
