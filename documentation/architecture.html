Architecture

Trois conteneurs Docker, une seule entrée pour le navigateur, et un backend qui parle à MySQL et à TMDB.

Vue d'ensemble

Navigateur
localhost:8080
→

/api →
backend (Express)

→

Le backend appelle aussi l'API TMDB en sortie (api.themoviedb.org et images image.tmdb.org).

Les trois services

ServiceImageRôlePort exposé
web nginx:1.27-alpine (build multi-étapes) Sert le build React, redirige /api/ vers le backend, sert /documentation/ depuis le dossier du projet. 8080 sur la machine hôte
backend node:22-alpine API REST Express. Au démarrage, lance les migrations puis le serveur, et planifie la tâche quotidienne. Aucun (accès uniquement via web)
db mysql:8.4 Stocke tout l'état de l'application dans le volume db_data. 3307 sur l'hôte (évite le conflit avec MySQL de WAMP sur 3306)

Pourquoi un proxy Nginx ?

Le frontend appelle son API avec un chemin relatif (/api/..., voir frontend/src/api/client.js). Nginx sert le front et l'API sur la même origine (localhost:8080), ce qui permet aux cookies de session de fonctionner sans configuration CORS complexe. Le proxy est défini dans frontend/nginx.conf.

En développement sans Docker, Vite joue ce même rôle : frontend/vite.config.js redirige /api vers http://localhost:5000.

Démarrage du backend

La commande de démarrage du conteneur backend est :

node src/db/migrate.js && node src/app.js
  1. Migration : migrate.js exécute les fichiers SQL de src/db/migrations/ et des ajustements idempotents. Elle peut être relancée sans risque.
  2. Serveur : app.js monte les routes sous /api, puis démarre le cron.

Si la migration échoue, le serveur ne démarre pas : c'est voulu, pour ne jamais tourner sur un schéma incomplet.

Organisation du backend

DossierContenu
src/app.jsExpress, CORS (FRONTEND_ORIGIN), cookies, montage des routes, démarrage du cron.
src/routes/Un fichier par domaine : auth, shows, movies, episodes, watchlist, stats, calendar, discover, search, friends, import.
src/services/tmdb.js (client TMDB avec réessais), showSync.js (import d'une série en base), showStatus.js (statut automatique), auth.js (JWT et bcrypt).
src/middleware/requireAuth.js : vérifie le cookie token.
src/cron/checkNewEpisodes.js : resynchronisation quotidienne à 6h.
src/db/connection.js (pool MySQL), migrate.js, migrations/*.sql.
scripts/import-tvtime.js : import ponctuel depuis un export TV Time.

Frontend

  • Routage : React Router dans src/App.jsx. Les pages sauf /login et /register passent par ProtectedRoute.
  • Session : context/AuthContext.jsx interroge /api/auth/me au chargement.
  • Erreur 401 : l'intercepteur de api/client.js renvoie vers /login.
  • Statuts : libellés et couleurs dans constants/status.js.
