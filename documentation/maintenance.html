Maintenance

Dépannage courant, points d'attention et dette technique connue.

Dépannage

SymptômeCause probableAction
La page répond 502 Bad Gateway sur /api/... Le backend ne tourne pas ou a planté (souvent une migration qui échoue). docker compose logs backend --tail 50. Corriger la cause, puis docker compose up -d --build backend.
Le backend redémarre en boucle (Restarting) Erreur au démarrage : migration, base injoignable, ou dépendance manquante. Lire les logs. Vérifier que db est healthy avec docker compose ps.
Erreur bind: address already in use au démarrage Le port 8080 ou 3307 est déjà utilisé. Arrêter l'autre programme, ou changer le port gauche dans docker-compose.yml.
La recherche TMDB ne renvoie rien TMDB_API_KEY absente ou invalide dans backend/.env. Vérifier le fichier, puis docker compose up -d --build backend (le .env est lu au lancement du conteneur).
Connexion refusée après un docker compose down -v Le volume de base a été supprimé : la base est vide. Recréer un compte. Les migrations se sont appliquées automatiquement.
Changement de code non visible L'image n'a pas été reconstruite (le code est copié dans l'image, il n'est pas monté). docker compose up -d --build. Seule la documentation est montée en direct.

Points d'attention sécurité

À traiter avant toute mise en ligne. L'environnement actuel est local.
  • Secret JWT : JWT_SECRET est obligatoire (32 caractères minimum). Sans lui, le backend refuse de démarrer, il n'y a plus de valeur de repli connue.
  • Mots de passe par défaut : root_local et tvtracker_local dans docker-compose.yml. Acceptables en local, à remplacer ailleurs.
  • Routes de maintenance ouvertes : clean-runtimes, refresh-runtimes et recompute-status ne sont protégées que par la connexion, pas par un rôle administrateur.
  • Limitation des tentatives : 20 requêtes par IP toutes les 15 minutes sur /api/auth/login et /api/auth/register. Le compteur est en mémoire, il repart à zéro au redémarrage du backend.
  • Cookie Secure : désactivé par défaut (HTTP local). Mettre COOKIE_SECURE=true dans backend/.env dès que l'application est servie en HTTPS.
  • Vulnérabilités npm signalées à l'installation : 2 modérées côté backend, 11 côté frontend (dont 6 élevées). Non corrigées pour l'instant ; npm audit détaille les paquets concernés.

Dette technique et limites connues

  • Aucun test automatique dans le projet.
  • Import TV Time : le fichier JSON source n'est pas versionné ; le script ne fonctionne qu'après régénération.
  • Migration : migrate.js mélange SQL et logique JavaScript. Chaque nouvelle évolution doit rester idempotente.
  • Relations polymorphes (ratings, notes, watchlist) : pas de clé étrangère, donc pas d'intégrité référentielle en base.
  • Bundle frontend : plus de 500 Ko après minification (avertissement Vite). Un découpage par route réduirait la taille.
  • Recharts 2.x : branche déclarée obsolète par npm ; une migration vers la 3.x est à prévoir.
  • README : garde les deux procédures (Docker en tête, WAMP ensuite). La partie WAMP reste utile si tu lances le projet hors conteneurs.
  • Payload TV Time absent : backend/scripts/tvtime-payload.json n'est pas dans le projet ; il faut le régénérer depuis l'export RGPD.

Workflow Git

Le dépôt est github.com/vicwks/TvTracker. Trois branches permanentes :

BrancheRôleOù elle tourne
devDéveloppement. Point de départ de tout développement.PC local
pre-prodRecette avant mise en production.Serveur externe (O2Switch), autre dossier
prodProduction. Branche principale du dépôt.Serveur externe (O2Switch), dossier de production
  1. Partir de dev à jour : git switch dev, puis git pull.
  2. Créer la branche de travail : git switch -c feat/<nom-du-developpement>.
  3. Committer, puis pousser : git push -u origin feat/<nom-du-developpement>.
  4. Fusionner dans dev une fois validé. pre-prod et prod ne reçoivent que des fusions depuis dev.

Données

La base Docker contient les données de l'ancienne base WAMP (tv_tracker), importées le 8 octobre 2026 à partir d'un dump mysqldump : 1 compte, 819 séries suivies, 41 996 épisodes vus, 176 films, 3 éléments de watchlist et 1 note. Le compte de test créé dans Docker a été supprimé lors de cet import.

Pour refaire un import depuis WAMP plus tard : démarrer WAMP (MySQL), puis exporter avec mysqldump -uroot --single-transaction --routines --triggers --databases tv_tracker --result-file=tv_tracker.sql. Importer ensuite dans le conteneur : docker compose exec -T db sh -c 'mysql -uroot -p"$MYSQL_ROOT_PASSWORD"' < tv_tracker.sql (après avoir supprimé la base existante, sinon les comptes entreront en conflit).
